## ⚠️ Spec alignment

Four items in the spec were verified against the installed libraries and are wrong or unworkable as written. Every one is a correction adopted before implementation, not an open question. Record all of them in `docs/decisions.md` (Task 1).

| ID | Spec says | Reality | Adopted correction |
|---|---|---|---|
| **C1** | §8 `fixed_ast = deep_copy(ast)` | `copy.deepcopy(Document)` copies `_part` and `_body` as two independent XML trees; `.runs` mutates one, `.save()` serializes the other. Mutations vanish with **no error** | Banned. Clone only via `Document(BytesIO(original_bytes))`. Enforced by a test that greps `autofix/` for `deepcopy` |
| **C2** | §9 "write `fixed_ast` back to OOXML" | The AST models ~10 attributes per run; regenerating from it destroys images, `sectPr`, headers/footers, numbering, hyperlinks, fields, footnotes, equations | AST is a **read-only projection**. Fixes are planned as data (`FixPlan` = ordered `FixOp`s) and replayed against fresh clones of the original bytes |
| **C3** | §9 "wrap modified runs in `<w:ins>`" | Correct for text edits only. Most fixes here are format-only, and Word represents those as `w:rPrChange`. Implementing §9 literally makes every font fix read to the author as *delete the sentence, retype it* | Three modes: `w:rPrChange` (format), `w:del`+`w:ins` (text), `w:ins` (insertion) |
| **C4** | §4 UI depends on `parser`/`validator`/`autofix`/`report` directly | Puts orchestration and error handling inside a Qt class — the exact code that can't be tested on Linux or reused by the CLI | Qt-free `pipeline.run(source, options, progress) -> PipelineResult` façade between UI and stages |

**Three unaddressed risks that decide whether results are trustworthy** (not in the spec):

1. **Effective formatting resolution.** Verified: on a stock document `run.font.name`, `paragraph.style.font.name`, and `styles['Normal'].font.name` all return `None`; `docDefaults/rPrDefault/rPr/rFonts` carries `w:asciiTheme="minorHAnsi"`. §5.1's "read `run.font.name`" reports `found: None` for **every run** of any manuscript that sets fonts at style level — most real ones. Needs a full resolver: run `rPr` → character style → paragraph style + `w:basedOn` chain → `docDefaults` → `theme1.xml`.
2. **The `global-font` fix silently no-ops.** `run.font.name = "Times New Roman"` leaves `w:asciiTheme` in place, and per ECMA-376 §17.3.2.26 it **wins**. Word renders the theme font while re-validation passes — a false-green FR-11. The fix must pop `asciiTheme`/`hAnsiTheme`/`cstheme`/`eastAsiaTheme` before setting `ascii`/`hAnsi`/`cs`.
3. **`Paragraph.runs` and `.text` skip `w:ins` and `w:hyperlink`.** `CT_P.r_lst` is `./w:r` only. A manuscript arriving with co-author tracked changes — common — has whole sentences invisible to the validator. Index with `.//w:r[not(ancestor::w:rPr)]`; extract text via one canonical `paragraph_text()` helper used everywhere.

**Locked decisions:** Windows VM available for Phase 7 · real `.docx` samples to be supplied by the user · CLI first, GUI last · caption repositioning and title-case are **flag-only** in v1 · PySide6 over PyQt (LGPL).

## Phase 2 — Document understanding

### 4. `[x]` Parser: effective formatting, AST, ElementIndex *(M3, ~4 d)*
`parser/{effective,ast_builder,binding,captions,shapes,ids}.py`. The highest-risk, highest-leverage work in the project — see spec-alignment risks 1–3.
- `[x]` `effective.py`: resolve run `rPr` → character style → paragraph style + `w:basedOn` chain (depth-capped, cycle-guarded) → `docDefaults` → theme fonts in `word/theme/theme1.xml`. Each AST field stores resolved value **plus its `source`**. Bold/italic/superscript/caps fall back to `False` (not `None`) when nothing in the chain sets them — unlike font name/size, Word has no "unknown" rendering for a boolean flag, only "off"
- `[x]` Canonical `paragraph_text(p_el)` used by the parser and caption/citation matching — reduced to `"".join(run_text(r) for r in ...)` once discovered that `CT_R.text` (python-docx) already translates `w:tab`/`w:br`/`w:noBreakHyphen` to their text equivalents; `run_text()` adds only the NBSP → space normalization. Word-count/segmentation/Gemini-payload call sites don't exist yet (Tasks 5/6/12) but will use the same function
- `[x]` `ids.walk_document()` over `body.iterchildren()` so paragraph/table order is true (`document.paragraphs` loses interleaving, which breaks caption-position logic) — one canonical walk shared by `ast_builder` and `binding`, so their ids cannot drift apart by construction. Table-cell paragraphs emitted into the flat `paragraphs` list tagged `in_table`/`cell` — §5.1 omits them, so `table-text-size` would have nothing to check. Merged cells (repeated `<w:tc>` across a horizontal/vertical span) de-duplicated by element identity
- `[x]` Figures via `body.xpath('//w:drawing | //w:pict')` then `ancestor::w:p[1]` — `document.inline_shapes` misses anchored and VML images and has no paragraph back-reference
- `[x]` `ElementIndex`: `p0042` → element, `p0042.r03` → run element via `.//w:p` and `.//w:r[not(ancestor::w:rPr)]`. IDs positional **at build time only**; the map then holds element objects, which survive reparenting (tested against a live caption move). Because each clone is byte-identical at build time, IDs match 1:1 across read/fixed/redline/annotated clones
- `[x]` `w:sz` is half-points (`w:val="18"` = 9pt); bold/italic tri-state (absent = inherit, `<w:b/>` = true, `<w:b w:val="0"/>` = false) — compare *effective* values, write *explicit* ones
- `[x]` **Found during implementation, not in the spec or the plan:** two id-stability bugs, both the same root cause — keying a lookup dict by `id(element)` without holding a reference to that element. A garbage-collected lxml proxy's memory address can be reused by an unrelated element, silently colliding two different paragraphs (or two different table cells) onto the same id. Fixed by keying on the element object itself, which keeps it alive for the dict's lifetime; see `ast_builder.py`, `ids.py` (merged-cell dedup), and `shapes.py`
- `[x]` **Also found during implementation:** the caption regex `Table\s+([IVXLCDM0-9]+)\.?` (optional trailing period) matched narrative prose that happens to start the same way a caption does — "Table I summarizes the primary outcomes." parsed as a caption. Fixed by requiring the period/colon (`[.:]`, mandatory) that a real caption always has right after the number; regression-tested in `test_parser.py`
- **Done when:** every §5.1 field populated on the compliant fixture ✅ and all real documents ✅ (five real submissions parsed without error, 2026-09-12) · resolution tests cover all four inheritance sources including theme fonts ✅ · parse→parse ID stability ✅ · input SHA-256 identical before and after parse (FR-9, asserted not assumed) ✅

### 5. `[x]` Segmenter *(M4, ~2 d)*
`segmenter/{headings,heuristics,section_index}.py`. The single largest source of *cascading* false positives — a title mislabelled as a heading fails `title-size`, `title-bold`, `title-case` **and** `heading-style` at once.
- `[x]` Heading detection as a **score**, not a branch chain: style name +3, all runs bold +2, literal uppercase +2, ≤8 words +1, no terminal period +1, vocabulary hit +3; ≥3 = heading. `outlineLvl` is not in the weighting — it isn't a field on `Paragraph` (Task 4 closed before this task started, and adding it now would be scope creep back into the parser); style name carries that signal alone
- `[x]` Normalize NFKC → casefold → strip leading enumeration → strip trailing colon → collapse whitespace; match exact → token-set (makes "materials and methods" ≡ "methods and materials" for free) → fuzzy ≥0.85, gated on the paragraph already clearing the structural threshold on its own — otherwise a references-list entry or a caption fuzzy-matches a section name
- `[x]` Front-matter state machine for title/author/abstract/affiliation — these have no headings (or, for abstract, one too short and unstyled to score reliably). **Reworked after real-document testing (2026-09-12):** the original design treated affiliation as "whatever comes after the abstract heading, defaulting the last paragraph to affiliation if no ORCID/email signal fires." All five real submissions falsified the ordering assumption outright — every one places each author's institutional/ORCID/email line directly under the author names, *before* the abstract — and the positional default produced a real false positive (a single-paragraph abstract body immediately followed by a "Keywords:" line had the abstract body mislabelled affiliation, since it was "the last paragraph before something already claimed"). Fixed by removing the positional default entirely: an ORCID/email string or a paragraph opening on a bare superscript digit (the numbered-affiliation-footnote convention) is now scored as affiliation wherever it appears in front matter, before or after the abstract alike; everything else defaults to author (pre-abstract) or abstract (post-abstract) with no positional guess for affiliation at all. **Deviation from this bullet's original wording:** corresponding-author is *not* handled here — in the compliant fixture it carries a real, bold, uppercase "CORRESPONDING AUTHOR" heading that already matches `corresponding_author_address`'s configured synonyms, so it resolves through the ordinary per-paragraph heading scan in `section_index.segment`, with no special-casing needed (none of the five real submissions carry a separate corresponding-author section at all — that content is folded into their author block, which the reworked affiliation scoring now also correctly captures)
- `[x]` **Synonym tables and `section_order` live in the rule config JSON, not in code** — `journal_v1.json` gained `"abstract": ["abstract", "summary"]` (so the Abstract heading resolves through the same vocabulary path as every body heading) and, after real-document testing surfaced three of five real submissions using the bare heading "METHODS" with no vocabulary match, `"methods"` was added to the `methods_and_materials` synonym list
- `[x]` `on_missing_section` on the rule schema — already landed in Task 2's `schema.py` (`BaseRule.on_missing_section`, default `skip`) ahead of this task; verified still present and used by nothing yet (Task 6's engine is what will read it)
- `[x]` Generated `section-present-*` rule family from `required_sections` (`acknowledgement` excluded — it's optional, so never in that list to begin with). Each rule targets `NodeType.DOCUMENT`/`SelectorScope.FIRST` with `condition.attribute = "section:<name>"` and `operator: is_non_empty` — there is no node to select for a section that doesn't exist, so this is a lookup key into `SegmentationResult.missing_sections` for Task 6's engine to resolve, not a paragraph/run attribute
- `[x]` `front_matter_only` degradation (`SegmentationResult.front_matter_only`, `MIN_BODY_HEADINGS = 4`) when fewer than 4 body headings are recognised, with `degraded_reason = "section boundaries undetected"`. Wiring this into "mark body rules `check_failed`" is Task 6's engine's job — this task only produces and tests the signal
- `[x]` Per-paragraph `section_confidence` and `section_source` recorded (`HEADING` / `POSITIONAL` / `INHERITED`)
- **Done when:** all 14 labels assignable ✅ (compliant fixture; the five real submissions detect 10/10 of their sections — none of them uses `acknowledgement`, `conflict_of_interest`, `funding`, or `corresponding_author_address` as a separate heading) · tested against compliant, scrambled-order (`violating("doc-order")`), and heading-variant (synonym-substituted heading text) fixtures ✅ and all five real documents ✅ (2026-09-12: zero missing required sections, correct document-order section transitions verified by hand for all five, `front_matter_only` correctly `False` for all five)
- **Verified 2026-09-12:** 271 tests pass (21 new) · ruff and mypy --strict clean · re-verified against five real manuscripts after the affiliation-heuristic rework above

## Phase 4 — Correction & output

### 8. `[x]` Fix planner + audit log + conflict detector *(M6, ~3 d)*
